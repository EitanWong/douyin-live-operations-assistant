协议字段核对参考 [TikTokLiveJava 的 webcast.proto](https://github.com/jwdeveloper/TikTokLiveJava/blob/master/API/src/main/proto/webcast.proto) 与 [opedium/douyin-live-proto 字段参考](https://github.com/opedium/douyin-live-proto/blob/master/docs/complete_payload_reference.md)：前者列出 `WebcastChatMessage.atUser = 12`、`WebcastMemberMessage.isSetToAdmin = 5` 和 `admin_permissions = 25`；后者记录聊天内容含 `@昵称`。实现使用结构化的 `atUser` UID，昵称文本仅作为协议缺字段时的兼容路径。协议仓库属于逆向分析资料，不是抖音官方文档；构造帧测试不能代替真实房间帧验收。

社区维护的[直播房间响应样例](https://github.com/mteverest/douyin-live/blob/main/%E6%8A%96%E9%9F%B3%E7%9B%B4%E6%92%AD%E7%9B%91%E6%8E%A7Api%EF%BC%9A%E7%9B%B4%E6%92%AD%E9%97%B4%E4%BF%A1%E6%81%AF.md)含 `admin_user_ids` 列表；实现仅当当前房间响应含格式正确的列表时，才用登录 UID 精确判定管理员/非管理员，字段缺失或错误时保持未知。该资料不是抖音官方契约，真实房间中的字段可用性尚待只读验收。`WebcastMemberMessage.isSetToAdmin` 与 `admin_permissions` 属于成员管理事件字段，不等同于当前登录账号的授权证明。未找到可验证的封禁接口或页面操作契约，因此违规阈值只发出提醒，不自动封禁；不从管理员弹幕或徽章猜权限。
