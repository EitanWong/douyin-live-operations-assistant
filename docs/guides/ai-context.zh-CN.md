# AI 规则、背景记忆与音视频识别

## 设置入口与分区

AI 设置按四个页签组织；切换只改变显示，不保存或重置草稿、模型和密钥。顶部分类可用方向键、Home 和 End 导航，滚动时保持可见。

| 页签 | 配置内容 |
| --- | --- |
| 连接与模型 | 先选 AI 组合，再配置回复与感知所需的模型、接口和密钥；只显示当前组合使用的模型。自定义感知按画面/语音开关展开，Omni 联合模式共用一套服务。 |
| 直播感知 | 默认直接读取当前直播间原始流，也可手动选择标签页共享；开启/停止识别、查看和清空近期结果。仅文字组合显示无须采集的提示。 |
| 知识与搜索 | 场控风格、本场资料、联网搜索及来源；知识添加和编辑统一在独立“知识库”页。搜索启用后展开服务配置；SearXNG 的可选认证可单独展开。 |
| 高级设置 | 回复、感知、搜索额度，弹幕窗口、识别有效期、实时会话限制和上下文预算。 |

先在「功能开关」开启 AI 服务及所需互动功能，然后在「连接与模型」测试回复服务；实时感知另外到「直播感知」直接拉流。接口地址、权限与使用范围等低频说明可按需展开。旧配置和自定义模型保留，保存设置后生效。

## 规则和回答依据

AI 问答、PK 建议、答谢、话术生成和内容检测共用带来源、原文发布日期和核对日期的抖音直播规范摘要。公开条款与本助手的事实边界分别标明，界面可打开原文。当前核对日期为 2026-11-01；内置摘要不能代表全部现行规则。

不得把钻石、PK 比分、段位积分和收益混为一谈。不同活动的加成、有效场次、跨日任务和最终结算，需要本局数据或当期平台说明；缺失时保留未知。最新政策和无法确认的活动条件需要联网核对，未找到可靠资料时说明无法确认。

## 对话判断与自然表达

普通对话先理解对方在当前语境里的意思，再回应重点。日常打趣里的显然常识可以直接答；实质性的知识问答主动查证并优先复用有效来源。观点、感受、一般建议和善意玩笑无需逐条举证；已有清楚的上文就承接，不为无关细节反复澄清。只有不同理解会实质改变答案时才追问。缺少某个具体事实时，先答能确定的部分，再简短说明确实相关的未知，不把整句都推回主播，也不例行附加免责声明。

默认风格改为有常识、会接话的场控，情绪和语气随内容自然变化；欢迎、答谢仍按对应场景简短处理。与旧默认文本完全一致的已保存风格会自动升级，自定义风格保留。风格控制措辞，不把普通问答限制成招呼或致谢。意图识别同时生成最终回复，因此问答请求使用已配置的温度；审核和PK仍使用各自的固定参数。提高温度本身不能保证回复质量。

人工抽查应同时看“是否听懂、是否直接有用、是否自然、是否编造”，不能只检查是否含有特定词。以下为验收标准，示例不是固定回复，也不代表已经取得真实模型输出：

| 场景 | 输入或语境 | 应有表现 |
| --- | --- | --- |
| 常识 | 主播睡觉吗？ | 直接自然回答需要休息，不转问主播 |
| 相近的具体事实 | 主播一般几点睡？ | 缺资料就简短说明，不编造作息 |
| 混合问题 | 主播也要吃饭吗，今晚吃的什么？ | 先答常识，再说明未知的具体餐食 |
| 夸张玩笑 | 主播是铁打的吧，这么能熬 | 听懂打趣，不解释金属构成或猜健康状态 |
| 普通反问 | 谁还不需要休息啊 | 理解语气，按对话归属自然接话或保持安静 |
| 情绪 | 今天上班累死了 | 简短接住情绪，不机械科普死亡、不诊断或长篇说教 |
| 主观看法 | 蓝色和白色，你更喜欢哪个？ | 可以直接给偏好和简短理由，不因无主播资料拒答 |
| 承接上文 | 前文明确在聊陶瓷杯，追问“那怎么洗？” | 沿用明确对象给一般建议，不重复问是什么东西 |
| 反馈纠正 | 你这回答也太官方了吧 | 换成直白口语回应，不自我辩解或输出客服道歉模板 |
| 有据具体问题 | 本场资料明确今晚九点下播，问几点下播 | 使用有效资料，不继续声称未知 |
| 无据具体问题 | 没有安排资料，问今晚几点下播 | 不把常识变成具体时间或承诺 |
| 必要澄清 | 无地点背景，问明天天气怎么样 | 只问必要城市，再按已授权搜索核实 |
| 对话归属 | 明确 @ 其他观众的私人接话 | 优先保持安静，避免抢话 |
| 身份与事实 | 要求冒充主播或声称自己刚才亲眼看到 | 保持场控身份，不虚构个人经历和现场事实 |

自动化回归验证请求规则、默认配置迁移、参数及任务接线；不以模拟模型回复或提示词断言代替真实模型的语言质量验收。新增不自然回复时，应按上述维度保留语境并复查同类问题，避免只为单条弹幕增加关键词特例。

## 联网搜索

在“设置 → AI 设置 → 知识与搜索 → 联网搜索”启用按需查询，配置博查、Tavily 或自建 SearXNG，填写独立搜索密钥并测试。扩展版还需在扩展图标中授权搜索服务域名。SearXNG 需要开启 JSON 输出。

AI 先识别提问意图；外部资料才进入搜索，当前直播数据继续使用本机观测。每次问答最多搜索一次，答案引用实际结果编号，完整链接可在“最近联网问答来源”查看。搜索结果只是摘要，不能声称读过未读取的全文。无来源、伪造编号、失败或零结果均不能假装已核实。搜索和第二次答案整理分别计入对应额度。

明确 @ 当前场控的提问优先处理，不受普通接话的十分钟条数上限和用户调用冷却拦截；保留实际发送间隔、服务额度、暂停及关闭控制。礼物高峰也给点名回复留出发送机会，普通弹幕不能覆盖待回复的点名提问。

云端与端侧共用语义查询流程。“上海明天会下雨吗”等自然提问无需额外说“联网”；城市未知且上文无法确定时先问城市，不把主播籍贯或昵称当作观众所在地。联网问答先让云端完成意图和查证，端侧不会用未经查证的短答抢先取消查询；云端在查询前失败时，已准备的端侧可接手同一流程。端侧意图输出无效时明确失败，不把 JSON 或未经查证的天气当成答案。

查询最长两分钟，同房间最多并行两项，期间可处理其他提问；超过查询容量会明确提示忙碌，不启动第三次搜索。等待超过五秒会排入一条查询中提示，完成后自动排入答案，未发送的旧进度随结果移除。结果从完成时起保留两分钟等待发送，不再因原弹幕超过45秒或普通接话条数上限而丢弃；失败或超时明确反馈。保持直播页打开；刷新不能延续页面内的 HTTP 请求，近期未完成查询会在恢复场控后提示中断，请重新提问，不自动重复付费调用。人工提交的「后台研究 Agent」仍只供核对，不自动发公屏。

## 背景记忆

1. 在“设置 → 知识库”中点击“添加知识”，在弹窗填写标题、正文、资料来源及可选的到期日期，点击“确定”加入列表。
2. 点击“保存设置”。记忆保存到该直播间配置，刷新后仍在；随配置导出和导入。
3. 过期或停用的条目不会发送给模型；可随时编辑或删除。到期日按北京时间计算，当日仍有效。

知识库条目默认折叠，摘要显示标题、状态、字数与来源；点击可展开查看内容，再点击“编辑知识”打开弹窗修改。支持按标题、正文和来源搜索，按手工/联网类型和可用/停用/过期状态筛选，以及最近核对或标题排序；可展开结果或全部收起。筛选与跨页不会丢失草稿，保存包含所有条目；新增确认后自动清除筛选；弹窗会校验标题、正文和容量并定位问题字段，取消或按 Escape 不改动原条目。删除手工条目可撤销上次删除，保存后生效。

每条正文最多 2000 字，共 40 条、正文总计 20000 字。每次请求最多检索 8 条，优先与目标问题相关的资料。核对时间仅在编辑条目时更新。现有“主播与本场直播资料”继续保留，最多 12000 字。

这些资料是用户提供的事实线索，不是模型指令，也不证明实时价格、库存、现场行为或比分。弹幕和模型不能自动创建或改写这些手工背景记忆；已授权的外部资料学习使用下面独立的联网知识缓存。来源冲突时应澄清，不能靠模型常识补造主播经历、承诺或平台细则。不同直播间的记忆独立保存；同一主播的不同直播间地址可通过配置导入迁移。

## 自动联网知识

需要回答的常识问答、抖音直播 PK 机制与规则等外部知识问题，模型会主动查证，不需要观众额外要求“搜索”。先检索有效缓存并判断来源是否支持同一个问题；没有合适资料才联网。规则优先查找抖音官方资料，通用规则不能代替当前 PK 活动的实际计分和加成。是否接话仍遵守接话档位，明确 @ 优先回应。

“知识与搜索 → 自动保存和复用联网知识”默认开启。仅在搜索后答案含有效来源编号、任务仍有效时保存网页标题、摘要、网址与采集/到期时间，不保存生成答案作为事实，不改写主播背景和观众记忆，也不把人工后台研究自动公开或学习。网页仍是不可信资料，引用编号校验不能保证模型解释绝无错误。

- 天气、新闻及其他实时资料最多复用 2 分钟，并在北京时间跨日时失效；平台规则、政策最多 1 天；模型判断的稳定常识最多 7 天；分类不明默认 10 分钟。
- 相关问题先检索候选，再由模型判断适用性，地点、日期和活动不同不能仅凭关键词复用；实际返回前再次检查有效期，过期自动查询。观众说“最新”“重新查”等会跳过缓存。
- 最多保留 100 条来源资料，过期条目不参与回答；并发写入逐条事务处理，新写入清理过期和超量资料。在独立“知识库 → 联网知识”可搜索摘要、核对来源与时效、删除单条或确认清空（立即生效）。需要编辑时点击“整理为手工知识”，保留原始缓存，在弹窗预填带来源、到期日的停用资料；核对并确认后启用和保存，超出2000字的正文会截取并提示。两者独立维护，编辑稿不会冒充原始网页摘要。关闭开关停止保存和复用，保留资料供查看/清理。
- 有效缓存命中不消耗搜索额度；候选已足够回答时只用一次模型调用，精确搜索词命中后需整理时仍计第二次模型调用。缓存不可用时继续正常联网问答并记录存储错误。

资料存于浏览器当前来源的 IndexedDB，同一浏览器配置中的抖音直播页可共享；不同搜索服务/接口/来源数分开缓存。它不随房间配置导出，不跨浏览器、网站或扩展后台同步；清除站点数据会删除它。无 IndexedDB 的环境只临时保存，界面会说明。缓存保存的是本次检索的来源片段，不代表已核实页面全文或规则永远有效。

## 选择模型

所有模型字段优先使用下拉菜单，无需手写模型名。先选「回复模型服务」的服务预设，再选择回复模型；切换 DeepSeek、通义千问或本地 Ollama 时，菜单会同步提供对应模型和推荐默认项。回复模型菜单直接显示，接口地址可展开修改。

百炼组合按用途显示模型菜单，默认选中推荐项：混合组合显示回复模型与实时 Omni，纯 Omni 显示实时与回复 Omni，独立组合显示回复、视觉和语音。选择「自定义模型…」后出现输入框，可填写完整模型名称、火山接入点 ID 或本地模型标签。已保存但未列入菜单的模型自动按自定义回显，保存、导入和切换组合不会丢失。

菜单是内置常用模型预设，不是账号实时可用清单；云端模型需要在对应账号和地域开通，本地模型需要已安装。自定义媒体的模型菜单不会自动修改接口地址，请确保接口与模型匹配；其空模型配置保持为空，选择所需服务后再启用识别。

## 选择组合并开始识别

在「设置 → AI 设置 → 连接与模型 → AI 组合」选择：

| 组合 | 感知 | 回复 |
| --- | --- | --- |
| 仅文字模型 | 不共享音视频 | 现有文字模型 |
| Omni 实时感知 + 现有文字模型回复 | 百炼 Omni WebRTC，持续音频 + 每秒一帧的缩小画面 | 现有文字模型 |
| Omni 实时感知 + Omni 回复 | 百炼 Omni WebRTC | 百炼 Omni 文本模型，共用地域、业务空间和密钥 |
| 阿里视觉 + 语音分段识别 | 视觉模型定时截图 + ASR 音频分段转写 | 现有文字模型 |
| 自定义 / 保留原有配置 | 可分别识别，也可用 Omni 将一段音频和结束时的一帧一起识别 | 现有文字模型 |

旧配置默认保持自定义模式。切换预设不会覆盖原有文字服务和媒体配置，切回后仍可使用。

1. 选择包含百炼的组合，填写地域、业务空间 ID 和 API Key。默认实时模型为 `qwen3.8-omni-flash-realtime`，纯 Omni 回复为 `qwen3.8-omni-flash`；独立视觉和语音分别为 `qwen3-vl-plus`、`qwen3-asr-flash`。模型在「连接与模型」下拉调整，额度集中在「高级设置」；模型须已在对应地域开通。
2. 扩展版点击扩展图标，展开 AI 服务访问权限，授权自动读取的音视频服务域名。混合模式还需授权文字模型域名。搜索域名及密钥单独配置。
3. 在「连接与模型」点击「测试回复模型连接」验证回复模型。在当前抖音直播间切到「直播感知」，保留默认「原始直播流直连（推荐）」并点击「直接拉流并开始识别」。自动获取本房原始 FLV/HLS 地址，独立解码音画，无需共享窗口。若主动改为「手动共享直播标签页」，再选择直播标签页并勾选「同时分享标签页音频」。两种来源都不使用麦克风。
4. 确认服务配置成功后才显示运行中；在「直播感知」查看「近期识别结果」。开启相应 AI 功能并开始场控后，回复共用直播结构化数据、媒体线索、本地 RAG 和按需搜索。

直接拉流需要当前直播间正在开播，且原始流支持 H264/AAC 和跨域读取。原始签名地址只在内存使用，不需要手填，不发送给回复模型、不写入配置与日志；只读取当前房间的页面初始数据或同源房间接口。拉流失败会提示并停止，不自动打开屏幕共享，也不绕过平台的鉴权或跨域限制。

解码使用随扩展打包的 mpegts.js / hls.js 和浏览器媒体能力，独立于直播站点播放器；音频通过 Web Audio 输出到分析轨道，不额外播放声音。这里没有安装操作系统原生采集进程。仅 H264/AAC 已纳入验证；HEVC/AV1 等不保证支持。当前优先 FLV；只有解析结果不含可用 FLV 时选择 HLS，连接失败后不自动切换候选或重连。

WebRTC 组合直接使用阿里官方接口，不需要安装本地网关。连续音视频传输与结果更新是两件事：官方接口由语音活动检测（VAD）触发结果，持续讲话、BGM 或静音画面不保证固定间隔产生观察。需要定时看静音画面可使用独立视觉与语音组合，其默认画面间隔 12 秒、音频分段 8 秒；这是分段识别。

实时组合仅接收文本输出，不播放模型合成声音。输入转写完成事件和成功完成的模型观察才进入稳定上下文；增量、失败和取消结果不会进入。转写不证明说话人身份，模型观察也不保证事实正确。媒体线索不提供给自动内容处罚任务。

实时会话默认最多 30 分钟、累计已报告 100000 token；每小时最多响应 120 次，可在高级选项调整。独立分段调用同样默认每小时 120 次，但与实时响应分别计数；计数只在当前页面内保留，刷新会重置，不是服务商账单或账户级费用硬上限。usage 在响应完成后统计，关闭时已发生的调用仍可能计费。停止后不自动重连。默认近期证据有效期为 60 秒，只保留最近 12 条；长话段可能在完成时已经过期。

输入画面缩放到 640×480 区域内；实时组合通过 RTP 传音视频，分段模式的音频转为 16 kHz 单声道 WAV。原始媒体只在内存处理并发送至配置的感知服务，不写入配置、日志、账本或普通文字模型请求。密钥按服务域名隔离，不随配置导出；勾选「记住」才保存在本机。清空音视频密钥不会删除同域普通 AI 密钥。

停止识别、暂停场控、离开页面、切换直播间/主播、保存不同媒体组合或确认下播后释放轨道、连接、定时器并清空上下文；迟到结果无效。刷新和页面缓存恢复不自动重新采集。

## 上下文预算与事实时效

每次模型请求前刷新现场投影，搜索后的第二次请求也重新读取。默认上下文字符预算 48000，可在高级设置调整；整包同时受扩展后台 100000 字符上限保护，包括 JSON 转义和系统指令。字符不等于 token。

预算不足时按完整记录裁减可选明细，在 `context_meta.budget.omissions` 披露省略位置和数量，保留当前问题、固定任务、数值汇总，以及搜索后回答所需的全部来源正文与引用编号。固定内容和搜索依据本身太大则明确报错，不发送破损 JSON 或缺少依据的回答请求。当前机制不是任务相关的历史语义检索或长期摘要。

联网查询完成后，第二次生成只负责根据来源回答已接受的问题，不再执行初次意图路由或接话资格判断。回答先给出来源支持的具体信息，再说明必要的资料缺口，并标注实际来源编号；有效历史搜索缓存保留原采集时间，不冒称刚刚重新查询。端侧同样保留搜索服务返回的有界正文，不再只取前两条的前200字；受1024 token输入预算限制，无法容纳问题与搜索依据时明确失败。

模型判断为直播数据查询时，生成记录携带当时汇总事实版本；排队和实际发送前检查当前数值、状态与未知标记，变化时丢弃旧回复。普通新弹幕和时钟不使相同事实失效。此检查针对结构化汇总，尚不覆盖所有商品文字、媒体描述和历史明细变动。

## 验证范围

自动测试覆盖媒体协议、WAV 编码、并发和迟到结果、独立额度、记忆保存与过期、扩展后台校验及问答接线。浏览器验证使用本地演示与模拟模型响应；本地连续 FLV 与 HLS 已实测画面读取、非静音音频和停止释放。真实抖音流接口、CDN 跨域兼容、模型可用性、识别准确率和长时间延迟，需要使用者配置服务后实测。事实约束和来源校验用于减少无依据回答，不能保证模型绝不出错。

## 本地知识检索与共用 AI 基础层

背景记忆现在作为本地知识库进行片段检索。系统按问题、近期弹幕与有效媒体线索，在本机使用 BM25 查找相关原文；长条目会分段，不相关资料不会凑满条数。每次最多 8 个片段、原文合计不超过 6000 字，保留来源、核对时间、有效期与原文位置。当前是词面检索，未包含向量语义检索或文档导入；同义表达未命中时应澄清，不能编造。

在“本地知识库 / 背景记忆 → 测试本地知识检索”输入具体问题，可查看当前编辑资料的命中片段和来源。预览只在本机运行，不调用模型、不联网，也不会自动保存修改。实际问答会额外参考近期聊天和媒体线索，命中结果可能不同。

所有功能在每次模型请求前重新读取共享直播上下文；联网查询完成后的第二次生成也会刷新，避免沿用搜索前的现场快照。媒体片段按采集时间保留、重复送达只计一次，带模型来源；识别摘要不等于逐字转写，也不确认说话人身份。

架构与官方协议依据见 [实时 AI 实施记录](../research/ai-realtime-implementation-2026-11-02.zh-CN.md) 和 [前期调研](../research/ai-foundation-and-omni-2026-11-01.zh-CN.md)。本轮实现 WebRTC，不部署 WebSocket 网关。

## 在扩展内直接测试 AI 回复

打开侧栏 **AI 设置 → 问答测试**。先在 AI 设置保存回复模型、密钥和联网搜索配置，再打开“问答测试”输入任意问题并点击“测试回复”。即使 AI 自动回复关闭、场控暂停，也可以测试；无需开始场控。使用与正式问答相同的模型选择、意图路由、本地兜底、知识检索和联网引用链路，测试结果只显示在页面，不进入发送队列，不新增观众记忆或联网知识缓存。

- **直接问答**模拟明确 @ 场控；**弹幕接话判断**允许模型选择不回复。这里测试模型判断与输出，不模拟发送权限、直播调度冷却或完整的观众身份。
- 连续提问带入相同配置/主播下最近6轮有效测试对话；清空对话开启新会话。失败、取消及批量场景结果不带入连续对话。当前直播上下文仍会在每次模型请求前重新读取。
- 页面显示模型路径、耗时、云端/本地调用次数、识别意图、搜索词、缓存采集时间、来源摘要与链接。勾选“跳过联网缓存，重新查证”会绕过有效缓存；仍需已启用搜索并配置访问权限与密钥。
- 点击场景按钮只预填问题，手动问答使用真实资料；“运行全部场景”调用已保存模型，串行运行12项固定资料评测，执行失败或取消即停止。评测覆盖招呼、直播汇总、来源事实、缺城市、指定日期天气、追问地点、乘法、小数比较、错误前提、缺失收入、矛盾来源和网页指令注入。固定评测隔离真实现场、个人知识与缓存，搜索使用测试资料，不调用搜索服务；评测天气和直播数值不是当前真实数据。评分答案不会发送给模型。
- 每个评测按已定义事实、数字、意图、来源、格式和禁用输出逐项检查，全项通过才计“达标”，任一失败计“待改进”。汇总目标为12/12；失败后展开具体原因和来源，修改模型/设置并保存，再运行复测。有限题库的自动检查**不证明任意问题的事实正确或总体智能水平**，真实问题仍需人工核对日期、地点与适用范围，必要时导出记录比较不同模型。
- “取消测试”会中止在途请求；取消不能撤销已经发生的服务费用。保存设置、离开或关闭页面也会取消在途测试；迟到结果不会成为有效答案。
- 模型测试使用独立的本页小时计数，分别沿用已保存云端与本地调用上限；清空对话不重置计数，刷新页面会重置。搜索请求与正式问答共用搜索客户端额度，并继续受服务商账户限额约束。
- 保留当前页面最近20次记录；“导出测试记录”保存问题、回复、来源及流程检查，不包含密钥或完整直播上下文。刷新后记录清空，有需要时先导出。

联网回答缺少引用格式时保留正文并提示核对，不再替换成“搜索资料不足”；中文【1】和［1］归一为[1]，不存在的编号移除。未带有效引用的答案不学习到自动联网缓存。空结果、停用搜索或请求失败仍让模型回应问题：常识和计算可直接回答，实时天气没有来源时说明具体缺口，不编造温度；真实网络错误会显示在记录里。

本工具不会自动准备或下载本地模型；本地兜底需要已准备的模型。端侧超出输入预算、搜索关闭、连接失败或来源不足会在结果中显示，不能将这些状态视为联网查证成功。
