# AI 规则、背景记忆与音视频识别

## 规则和回答依据

AI 问答、PK 建议、答谢、话术生成和内容检测共用带来源、原文发布日期和核对日期的抖音直播规范摘要。公开条款与本助手的事实边界分别标明，界面可打开原文。当前核对日期为 2026-11-01；内置摘要不能代表全部现行规则。

不得把钻石、PK 比分、段位积分和收益混为一谈。不同活动的加成、有效场次、跨日任务和最终结算，需要本局数据或当期平台说明；缺失时保留未知。最新政策和无法确认的活动条件需要联网核对，未找到可靠资料时说明无法确认。

## 联网搜索

在“设置 → AI 设置 → 联网搜索”启用按需查询，配置博查、Tavily 或自建 SearXNG，填写独立搜索密钥并测试。扩展版还需在扩展图标中授权搜索服务域名。SearXNG 需要开启 JSON 输出。

AI 先识别提问意图；外部资料才进入搜索，当前直播数据继续使用本机观测。每次问答最多搜索一次，答案引用实际结果编号，完整链接可在“最近联网问答来源”查看。搜索结果只是摘要，不能声称读过未读取的全文。无来源、伪造编号、失败或零结果均不能假装已核实。搜索和第二次答案整理分别计入对应额度。

## 背景记忆

1. 在 AI 设置中点击“添加背景记忆”，填写标题、正文和资料来源，可设置到期日期。
2. 点击“保存设置”。记忆保存到该直播间配置，刷新后仍在；随配置导出和导入。
3. 过期或停用的条目不会发送给模型；可随时编辑或删除。到期日按北京时间计算，当日仍有效。

每条正文最多 2000 字，共 40 条、正文总计 20000 字。每次请求最多检索 8 条，优先与目标问题相关的资料。核对时间仅在编辑条目时更新。现有“主播与本场直播资料”继续保留，最多 12000 字。

这些资料是用户提供的事实线索，不是模型指令，也不证明实时价格、库存、现场行为或比分。弹幕和模型不能自动创建或改写记忆。来源冲突时应澄清，不能靠模型常识补造主播经历、承诺或平台细则。不同直播间的记忆独立保存；同一主播的不同直播间地址可通过配置导入迁移。

## 开始音视频识别

1. 在“直播音视频识别”选择画面、语音或两者。分别填写对应服务的完整 `/chat/completions` 地址和模型名。视觉需支持 `image_url`，音频需支持 `input_audio` 的 WAV 输入并返回文本。普通文本模型不能识别音视频。
2. 填写相应 API Key。视觉与音频可以用不同服务，同域共用音视频密钥；留空可复用已保存的同域普通 AI 密钥。勾选“记住”可保存到本机私有存储，密钥不随配置导出。扩展版将对应接口填入扩展图标中的 AI 接口地址并授权域名。
3. 点击“选择直播标签页并开始识别”，在浏览器选屏窗口选择实际直播标签页，勾选“同时分享标签页音频”。未共享到音频时会明确提示，不改用麦克风。
4. 查看“近期识别结果”。截图默认每 12 秒一次，音频默认每 8 秒一段，属于近实时采样；延迟还取决于网络和模型。只有最近 60 秒的识别摘要进入普通问答，原始媒体不进入普通问答。

每路识别串行执行，忙时跳过，避免越积越慢。音视频独立限额，默认每小时最多 120 次；连续识别失败或额度用完后停止，恢复后需手动再开启。原始截图和音频片段只在内存短暂处理并发送至所配置的媒体服务，不保存到配置、日志或账本。截图最长边限制在 640×480 区域内，音频转为 16 kHz 单声道 WAV。

点击“停止识别”、暂停场控、离开页面、切换直播间或已确认下播都会释放共享并清空上下文。停止前的迟到响应不会写回；清空上下文也会拒绝此前采集的迟到片段。刷新和页面缓存恢复不会自动重新采集。

共享内容可能含主播、连麦者或其他声音，不能只凭模型转写确认谁在说话。识别内容可能出错；音视频摘要不传给自动内容处罚判定。此实现没有接入 WebSocket Realtime 连续音视频模型，不能保证逐帧、逐字或整场无遗漏。

## 验证范围

自动测试覆盖媒体协议、WAV 编码、并发和迟到结果、独立额度、记忆保存与过期、扩展后台校验及问答接线。浏览器验证使用本地演示与模拟模型响应；真实模型可用性、识别准确率、直播标签页音频共享和长时间延迟，需要使用者配置服务后实测。事实约束和来源校验用于减少无依据回答，不能保证模型绝不出错。

## 本地知识检索与共用 AI 基础层

背景记忆现在作为本地知识库进行片段检索。系统按问题、近期弹幕与有效媒体线索，在本机使用 BM25 查找相关原文；长条目会分段，不相关资料不会凑满条数。每次最多 8 个片段、原文合计不超过 6000 字，保留来源、核对时间、有效期与原文位置。当前是词面检索，未包含向量语义检索或文档导入；同义表达未命中时应澄清，不能编造。

在“本地知识库 / 背景记忆 → 测试本地知识检索”输入具体问题，可查看当前编辑资料的命中片段和来源。预览只在本机运行，不调用模型、不联网，也不会自动保存修改。实际问答会额外参考近期聊天和媒体线索，命中结果可能不同。

所有功能在每次模型请求前重新读取共享直播上下文；联网查询完成后的第二次生成也会刷新，避免沿用搜索前的现场快照。媒体片段按采集时间保留、重复送达只计一次，带模型来源；识别摘要不等于逐字转写，也不确认说话人身份。

完整设计、官方接口依据和下一阶段的实时接入见 [AI 基础层与 Omni 架构调研](../research/ai-foundation-and-omni-2026-11-01.zh-CN.md)。真正的 Omni Realtime WebSocket / WebRTC 通道尚未接入，当前仍为分段近实时识别。
