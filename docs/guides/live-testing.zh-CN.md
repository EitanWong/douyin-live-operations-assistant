# 本机扩展实测

测试准备日期：2026-10-18。本机开发构建保持 0.1.1 版本号，包含当前 `dev` 工作区改动；GitHub Release 附件可能尚未包含这些改动。

## 加载本机版本

1. 在 Chrome 地址栏输入 `chrome://extensions`，开启右上角“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择项目下的 `dist/chrome-extension` 文件夹，文件夹内应直接有 `manifest.json`。已经加载该目录时，点击扩展卡片上的重新加载按钮。
3. 如同时安装了油猴兼容版或另一份场控扩展，先停用重复版本。
4. 登录抖音并打开一个真实的 `https://live.douyin.com/数字房间号` 直播页，刷新页面。
5. 页面出现“场控”按钮后打开面板；也可点击扩展图标，再点“打开直播间面板”。`127.0.0.1:4178` 是模拟器，不承担扩展实测。

## 首轮检查

开发联调可先运行 `npm run dev`，然后仅首次按上方步骤重新加载扩展、刷新直播页。Chrome 120+ 会显示“抖音直播运营助手 · 开发”；之后保存源码会自动构建、重载扩展并刷新直播页。保持监听终端运行，停止后正常场控照常可用。自动刷新保留配置与账本，但已保存的运行快照和未确认事件日志会在刷新后恢复；需要自动开始时，在该主播的运行规则开启自动开始。正式发布包没有这个本地更新通道。

1. 在“设置 → 连接诊断”核对主播和当前登录账号。本人过滤依赖准确账号 UID；自动识别失败时，在“主播与账号识别”里关闭登录账号自动识别，填写登录账号 UID。房间号不是账号 UID。
2. 点击“检查连接与发送控件”，观察直播连接、帧接收和解析结果；没有真实事件时不能判定礼物、欢迎和点赞已通过。
3. 在“设置 → 功能开关”开启要测试的模块，先测试礼物感谢、进场欢迎和点赞感谢；在“运行规则”选择“仅预览，不发送”，保存并开始场控。
4. 在“连接诊断 → 运行记录”观察实际事件。用当前账号点赞不应生成感谢；收到其他观众点赞时应生成预览。真实送礼事件出现时，核对发送者、礼物数量、连击和阈值；本人送礼不应生成感谢，也不进入近期送礼与收入估算。同名但不同 UID 的观众仍应正常处理。
5. 欢迎默认要求荣誉 ≥ 30 级、本房粉丝团且已点亮；没通过条件或资料缺失时不欢迎。礼物默认按连击总价 ≥ 1 钻感谢。核对规则后再判断有没有漏处理。

## 真实发送与 AI

- 预览结果符合预期后，将“运行规则”的回复方式切换为“自动发送”，保存并重新开始。先开启少量模块，观察实际公屏回显；新配置默认自动发送，发送控件按队列顺序串行处理，运行规则不设置全局发送频率上限。
- “已提交”表示已触发页面发送控件且编辑器已清空，仍需在公屏确认平台接受。点击前控件不可用或状态保存失败会重试；点击后回显超时、结果未知或刷新恢复时不自动重发，避免重复弹幕，后续消息继续处理。随时可点击“立即暂停”。
- AI 设置入口始终可访问。填写接口、模型及密钥后，在扩展弹窗的“AI 服务访问权限”授权对应域名，并点击“测试 AI 连接”。然后在功能开关启用 AI 服务及需要的 AI 模块；AI 服务开启后，各互动模块才提供 AI 生成选项。预览模式也会调用所选 AI 服务。
- 刷新直播页后按该主播的自动开始配置恢复；未开启时手动开始。切换房间或发送异常暂停后，应检查状态再开始。

## 稳定性复测

- 单页开始 → 暂停 → 再开始，以及发送异常后再开始，不应误报另一标签页占用。
- 同一房间打开两页：只能一页运行；暂停或关闭运行页后另一页可开始。
- 安静房间没有弹幕、网络短暂重连、控件重绘或单条发送失败都不应自动暂停；恢复后继续发送。只有用户明确点击暂停。
- 编辑设置时按 Enter 不应开始或暂停场控，输入法和按键长按不应触发切页/启停。
- 浏览器后退再返回页面，保持暂停，但可以重新开始。
- 不需要清除配置或账本。详见[稳定性审查](../reviews/stability-review.zh-CN.md)。

记录触发动作、预期结果、实际结果及发生时间；附“连接诊断”结果或脱敏后的运行记录。不要提供 Cookies、API Key 或登录令牌。自动测试通过不代表真实抖音推送、编辑器发送或服务账号权限已验收。

## PK 比分与预测

1. 重新加载本地扩展，再刷新直播页；刷新前自行保存未发送的弹幕草稿。确认自动识别的主播 UID 属于当前直播间。
2. 在真实双人 PK 中打开“PK 预测”的“PK 局势看板”，逐次对照平台双方比分与更新时间；中途进入也应在收到累计比分推送后显示，已观测的零分应显示为 0。
3. 核对双方归属、倒计时及结束分数；重复开始/结束推送不应清空比分或增加历史场数。场控暂停时仍可更新 PK 数据，PK 统计不发送弹幕。
4. 仅收到一方分数或无法确认主播身份时，另一方保持 `--`，预测保持未知。普通连麦和送礼用户 ID 不应变成 PK 分数。
5. 切换“近 1 分钟 / 近 3 分钟 / 本场全部”，核对比分和分差曲线；贡献榜只显示平台明确给出的 PK 贡献分，明细里的礼物钻石独立展示。未收到贡献榜时应显示等待信息。
6. 比分超过 15 秒未更新应降低可信程度，超过 60 秒不继续给出有效预测；弹幕持续到达不能让旧比分恢复新鲜。倒计时归零后等待平台终局推送，不提前宣布胜负。
7. 暂停场控，核对比分仍更新、最近 10 分钟活动图仍记录弹幕/进场/礼物；礼物连击只计增量。切换明暗主题、收起再展开和缩窄窗口后图表应适应面板。

本地可先运行 `npm run build`、`npm run demo`，在规则实验室点击“模拟 PK 追分局”和“模拟终局”查看图表。模拟数据不连接真实直播间，不作为协议或预测准确率的实测证据。

本次更新会使旧解析产生的比分快照和胜负样本失效，重新积累已核对的 PK 数据。字段依据与验证边界见 [PK 比分协议核对](../research/pk-protocol.zh-CN.md)。

## 日期账本与多主播

1. 在“设置 → 功能开关”启用收入统计；场控保持暂停，也应记录真实收到的其他观众礼物。
2. 查看“直播互动 → 收入统计”，核对当天已知钻石面值、未知单价数量和收入估算。刷新页面后核对金额未清空、重复推送未重计。
3. 在“设置 → 主播管理”添加第二个直播地址，打开并配置不同的礼物阈值、AI 模型和换算比例；返回第一个直播间核对设置仍独立。
4. 在收入统计切换主播与月份，核对日明细和月总额。修改收入比例仅影响之后收到的礼物，不应追溯修改旧金额。
5. 关闭收入统计后导航入口隐藏、停止采集，重新启用应恢复旧账本。导出所选月份可保存本地报表；卸载扩展会清除扩展本地账本。
6. 若出现“扩展已更新，当前页与后台断开”，先在“连接诊断 → 采集与存储”导出恢复数据，再刷新页面并导入礼物恢复数据。后台断连时也应能导出内存里的待入账记录；重复导入不应重计，跨月恢复应保留原采集日期。这个导出降级能力从本次修复开始提供，旧版本断连后可能无法导出。
7. 开发模式更新前，直播页必须确认已保存待入账恢复点；保存失败时应暂缓更新。核对礼物卡片在保存失败时显示待入账组数与旧账本状态，不再笼统提示全部已保存。

榜单估值会按天按 UID 去重，跨页面刷新、后台重启和 90 天以上间隔继续保留。收入统计关闭时仍可按配置继续或停止采集，当前行为以面板开关和[使用指南](usage.zh-CN.md)为准。

已在用户指定直播页只读核对：编辑器为 contenteditable 的富文本，发送按钮为带禁用属性的 SVG 图标，输入后会切换为可发送状态。修复改为冒泡 MouseEvent，并等待输入框清空确认页面处理；未使用登录账号向公屏发送测试弹幕。
