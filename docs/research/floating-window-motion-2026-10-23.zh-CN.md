# 悬浮窗口交互与动效

调研与实现日期：2026-10-23。

## 设计依据

采用 Apple HIG 的动效方向：反馈直接、关系明确、层级清楚，动画服务于操作；减少动态效果时仍保留状态反馈。参考 [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[WWDC18 — Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/) 和 [WWDC23 — Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/)。具体的可打断交互和速度连续性以两场 WWDC 的示例与讲解为依据。

重点落实三件事：拖动时由用户直接控制位置；松手时把速度交给后续运动；改变意图时从当前位置与速度转向新目标。弹簧不等于反复回弹，运营工具采用无振荡的临界阻尼，减少长时间使用时的视觉负担。

## 开源项目与组件比较

| 项目 | 调研内容 | 本项目的取舍 |
| --- | --- | --- |
| [Motion](https://github.com/motiondivision/motion)、[animate 文档](https://motion.dev/docs/animate) | 物理弹簧继承手势和已有动画的速度；按时长生成的弹簧与物理弹簧不同 | 保留持续的位移、速度和目标，不用固定时长关键帧冒充可衔接的弹簧 |
| [React Spring](https://github.com/pmndrs/react-spring)、[SpringValue 源码](https://github.com/pmndrs/react-spring/blob/next/packages/core/src/SpringValue.ts) | 持续的动画值、改目标、到静止后停止计算 | 为每个运动通道保存状态，全部静止后取消帧循环 |
| [Vaul](https://github.com/emilkowalski/vaul)、[作者的实现记录](https://emilkowal.ski/ui/building-a-drawer-component) | 速度投影、越界阻尼、指针捕获；父节点 CSS 变量影响复杂内容的拖动性能 | 直接写 transform，不逐帧写继承变量；只在松手时接管拖动 |

这是原生 JavaScript 与 Shadow DOM 项目。引入 React 组件会增加框架负担；现有构建同时输出 Chrome 扩展与单文件用户脚本。因此实现一个局部、无新增依赖的控制器，数学求解与交互代码自行编写，未复制上述项目源码。这里统一的是 Apple 的交互原则，不是对原生 AppKit / SwiftUI 的像素级复刻。

## 实际行为

- 开启与收起：从悬浮按钮方向轻微缩放、淡入淡出；退出更快。反向操作保留动画进度和速度，不等待上次结束。开始关闭时立即移除面板的交互与焦点访问，收敛后才隐藏；重新打开会立即恢复交互。
- 悬浮按钮：拖动无位置缓动延迟。松手时用最近采样的速度预测左右吸附边，纵向保留短距离惯性；吸附途中可以重新抓住，不会跳回目标位置。边缘有克制的吸附指示，中线迟滞避免指示左右闪动。
- 越界拖动：超出边界后增加阻力，最大额外位移为 24 像素；取消、失去捕获、窗口失焦或停止后松手不会沿用过期的甩动速度。
- 窗口：标题栏拖动移动；八方向边角缩放，默认最小 320 × 360 像素，视口更小时继续缩小以保持可用。手动调整后记住尺寸和位置；视口暂时缩小时约束实际尺寸，不覆盖用户偏好尺寸。
- 重置：双击标题栏或缩放角恢复默认布局。右下角控件支持方向键，每次 10 像素；Shift 加方向键每次 40 像素，Home 重置。Escape 收起窗口；手势进行时先结束手势。收起后焦点回到悬浮按钮。
- 响应式：窗口本身是查询容器；560 像素以下表单与主播统计重排，400 像素以下导航改为横向滚动，520 像素以下高度压缩固定区域，极短视口允许整窗滚动。表格保留局部滚动，图表沿用 ResizeObserver 调整尺寸。悬浮按钮位于打开的窗口下层，避免遮住标题和关闭控件。
- 减少动态效果：移除空间位移与按压缩放，保留短暂透明度反馈；系统偏好变化会结束正在进行的空间运动。

尺寸与位置仅存储在当前站点的 localStorage，不新增扩展权限或网络请求。兼容旧版仅有 left / top 的按钮位置记录。

## 实现与性能边界

`src/ui/spring.js` 使用临界阻尼的解析解，状态是位置、速度、目标。改变目标不会重置速度；延迟帧不会引发数值积分不稳定。开启动效的频率为 26，退出为 34，吸附为 22；这些是本项目的调校参数，不是 Apple 官方参数。

`src/ui/floating-window.js` 用一个 requestAnimationFrame 循环协调动画。指针事件合并为每帧一次写入；位移、按压、存在状态各自只有一个 transform 所有者。移动与开关只改变 transform / opacity，不动态改变模糊半径。缩放需要真实布局以让内容重排，按帧更新宽高；图表由已有观察器同步响应。

JavaScript 动画仍受宿主页主线程繁忙影响，不能据此承诺所有真实直播页都固定达到 60 / 120 fps。当前验证覆盖本地 Chromium 模拟页和确定性测试，真实直播页、实体触屏与软键盘仍需现场检查。

## 验证

- 弹簧测试：60 / 120 Hz 与延迟帧的结果一致；反向时保留位置和速度；静止后停止更新。
- 交互测试：快速开关、退出中反向、焦点恢复、松手惯性、吸附中抓取、额外触点、丢失捕获、八方向缩放、键盘操作、存储恢复、视口变化、减少动态效果和销毁清理。
- Chromium：真实鼠标移动与缩放、连续反向开关、窄容器的页面切换、亮暗外观、小视口和极短视口；检查页面横向溢出与关闭控件的可访问性。
- 构建：Chrome Manifest V3 与单文件用户脚本共用控制器，构建产物执行语法检查。

## 宽窗口的信息布局

按工具窗口的可用宽度采用渐进展示，保留同一份 DOM 和阅读顺序。低于 800 像素以单列为主，PK 比分、核心判断、比分趋势和贡献榜直接可见，其余分析用原生 details 按需展开。800 像素起切换为双栏：比分与追分推演并排，比分趋势与分差图并排，贡献榜与直播活动并排；主播统计、礼物页、AI 设置和账本也利用多栏组织内容。1100 像素起，主播统计与功能开关可使用三栏。短而宽的窗口降低图表高度，固定区域仍由原有高度断点压缩。

展开选择在宽、窄两种布局中分别记忆，生命周期为当前面板；纯尺寸变化不会反复重置用户选择。焦点在内容中时，收起会延迟到用户离开，避免丢失当前操作。表单不重挂载，草稿与已有配置不因布局切换而丢失。

四张 ECharts 图表分别观察自身尺寸，按帧合并尺寸更新；重算数据与刻度密度在尺寸变化停止 120ms 后进行。时间刻度、贡献者标签宽度按每张图表实际空间调整。窄图保持全部样本和前八名贡献者，未知分数仍为 null。收起的分析不初始化零尺寸图表，展开后通过尺寸观察绘制。

验证覆盖 1240 / 620 / 360 像素工具宽度、实际拖动跨断点、明暗外观、折叠后重新绘图、多页面横向溢出，以及展开选择与焦点的行为测试。图表演示使用明确标注的本地模拟数据。
