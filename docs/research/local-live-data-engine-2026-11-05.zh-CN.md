# 本地直播数据引擎、开源预测模型与采集能力调研

日期：2026-11-05，北京时间。范围：本项目当前源码与下列开源项目的一手资料。用户已明确要求：本机功能优先，验证本机后再做远程。本文区分本次实现与后续计划，不把模型论文成绩当成直播场景实测准确率。

## 目标架构

```text
本房 MAIN 观测器 ─┐
对手只读采集页 ──┼─ 校验、按文档/批次标识 ─ IndexedDB 待写队列 ─ Native Messaging ─ SQLite WAL
授权公开账号采集 ┤                                                        │
原始预测/终局标签 ┘                                 事实查询 / JSONL / 备份 / 数据集 / 训练
                                                                          │
                                              有界事实摘要、独立模型候选 ─ AI 和分析模块
```

SQLite 是持续归档与训练证据仓库；原账本仍是礼物核算的唯一来源；原有分析 IndexedDB 仍负责分钟特征、场次汇总和现有预测。恢复 journal、聊天上下文、滚动分析档案都不能替代长期归档。不把原始礼物连击消息直接求和，不从 PK 积分反推人民币。

## 已实现与边界

| 维度 | 本次可以交付的能力 | 未知 / 后续工作 |
| --- | --- | --- |
| 本房直播 | 持续归档已有解码器产生的弹幕、礼物、进场、人数/榜单、PK、粉丝团、连麦、活动、电商等事件，以及协议原帧分片 | 解码器未识别的内容保留原帧供后续分析，不等于已提取全部语义；平台没有下发的内容无法恢复 |
| 整场证据 | 原始时间、独立接收时间、房间、主播、来源和覆盖/缺口计数；数据库无自动按45天清除 | 整场完整性仍取决于开播前接入、连接持续性、缺口与终局证据；关闭浏览器不能继续采集，不是录像或完整音视频录制器 |
| 对手 | 从扩展菜单打开最多3个后台独立采集页，与本房建立来源关联；不启动场控、不发送互动；原文弹幕和礼物事件入同一数据库 | 需提供可访问的房间号/链接；不自动保证从主播UID解析出正确房间；平台登录/验证由用户正常完成；没有绕过反爬/验证码 |
| 主播/账号 | 既有公开账号采集的结果保存到本地仓库；保留公开主页与作品来源 | 不宣称公开主页等于完整后台经营数据；账单仍需授权导入 |
| 观众 | 稳定UID/secUid分开归属，保存已观察互动；查询所选观众的消息计数、明确兴趣表达和原话证据 | 不能得到全部潜水观众或所有关注列表；不按昵称合并；不推断健康、政治、宗教等敏感属性，不从送礼推断财力、心理或私密喜好 |
| 本机训练 | 已发布数值预测与后到实测配对；导出JSONL；残差校准模型按时间隔离训练/验证/测试 | 目前原始特征是已发布预测的点与上下界，尚非全量行为GBDT；真实样本不足时返回数据不足 |
| 本机推理 | 原生组件独立进程推理，已验证候选分别提供给AI，不覆盖原始预测 | 只有留出验证通过的目标返回候选数值；现有主图表继续展示原始发布预测，避免事后改写评分记录 |
| PK训练 | 保存 battleKey、剩余时间桶、当时胜率和已确认终局，导出按战局可分组的数据集 | 当前胜率仍是已有计分路径模拟；本次未用真实比赛训练分类器或证明校准效果 |
| 远程 | 数据格式与处理边界可复用 | 本次不启用远程存储/推理，不上传整场原始数据；待本机实播回测通过后再实现 |

“能采集”与“全部观众、所有维度、整场零丢失”是不同结论。采集页会受浏览器后台调度、网络、系统休眠、平台接口变更和磁盘状态影响；沿用现有保活租约，缺口保留为缺口，不补零。复制两个采集页会保留两份观测证据，不能把两份直接当两次业务事件。

## 怎样把准确率做实

1. **先核准目标。** “今日收入”要区分北京时间自然日、本场已观察礼物价值、预计剩余增量和实际结算。未掌握下播时间时给多个剩余时长情景；人民币依赖授权账单校准的结算系数。
2. **统一特征时点。** 每条样本保存asOf、目标到期、特征版本、单位、场次、缺测掩码、来源延迟。预测后来的弹幕、终局、未来榜单和事后补全单价不能出现在当时可见的特征中。
3. **选模型靠时间留出。** 本次本机模型按非重叠窗口取样，至少50条，前60%训练、中20%验证、后20%测试；训练标签必须早于验证起点，验证标签早于测试起点，清洗后各段至少10条。验证和测试MAE都改善至少5%才激活；重训不通过会停用旧候选。保留测试集误差与区间覆盖率，不用训练集拟合效果宣称准确。
4. **数值预测分任务评估。** 礼物/收入用MAE、WAPE（总真实值为0时不定义）、分位数pinball loss、区间覆盖及宽度；人数另评1/5/15分钟；日/月预测按整场/整日对齐，不能把分钟区间直接相加。
5. **PK概率单独验。** 按战局分组和时间切分，分开评估剩余120/60/30/10秒；使用Brier、log loss、校准曲线和每桶样本量。不同时间桶的同一战局不能跨训练/测试。确认平局用三分类，不把“未确认终局”当失败。
6. **集成不是盲目平均。** 同时段基线、现有统计、CatBoost/LightGBM、Chronos先保留独立预测。只用过去验证集选择/加权，校准区间；按主播收缩到品类先验以处理冷启动；漂移时回退可验证基线。
7. **语义与数值分工。** 小型中文分类器/embedding识别明确话题与文本意图，LLM负责解释可追溯事实；不让LLM编一个收入、读心概率或缺失对手弹幕填补事实空白。

本次合成样本仅验证训练/推理程序、留出门控和防泄漏；**没有真实主播训练集、真实PK回测成绩或可承诺的准确率提升百分比**。

## 本机完成后再做的扩展

优先积累跨场次真实标签，再增加按分钟的特征快照、可确认开播/下播的整场目标和授权结算标签；随后以CatBoost/LightGBM作为监督模型对照，并评估Chronos的收益和设备成本。对手房间自动发现、面向所选公开主页的限流任务队列、更多协议解码和持续实播压力测试仍需逐项验收。

远程阶段复用同一证据/目标数据契约，独立实现认证、批次幂等、上传范围、断线重试和数据删除；不得把配置密钥或整场数据随模型调用默认上传。服务器模式不能反过来成为本机采集、查询或推理的前置依赖。
