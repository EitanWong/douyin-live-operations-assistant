# 统一布局层：复用 Mantine，移除相互竞争的结构规则

## 决策

继续使用已锁定的 React 19.3.1 / Mantine 9.7.4，不新增 UI 框架。现有问题来自布局规则的所有权，而不是缺少组件：源 DOM 的 Grid / display:contents、可见 React 的 Stack，以及卡片 align-self:start 同时决定尺寸。真实浏览器中，AI 回复服务卡片被收缩至约 34px；只检查页面总宽是否溢出无法发现这种问题。

Mantine 是项目已经接入、已有主题适配和离线打包的成熟组件库。本次核对已安装实现和官方文档，使用其原生能力：

- [SimpleGrid](https://mantine.dev/core/simple-grid/)：容器响应式卡片、字段和指标；以浮窗容器而不是直播网页宽度排版。
- [Stack](https://mantine.dev/core/stack/) / [Group](https://mantine.dev/core/group/)：统一纵向节奏、操作区换行和对齐。
- [Tabs](https://mantine.dev/core/tabs/)：统一 AI / 主播分类、方向键切换和可访问关系。

React Grid Layout / GridStack 主要解决用户拖拽、缩放仪表盘单元，本产品目前需要的是表单和数据区的自然排布，接入会引入另一套尺寸和持久状态。Chakra / Ant Design 是替换整个设计系统的方案，与现有 Mantine 主题和 Shadow Root 适配重复。瀑布流会改变视觉扫描顺序，不能解决表单宽度和键盘阅读顺序，因此不引入。以上为适配性判断，不是上游性能或维护活跃度的排名。

## 单一布局契约

`src/ui/product/layout.js` 在兼容边界统一解释源结构：

| 术语 | 含义 | 可见组件 |
| --- | --- | --- |
| cards | 功能卡片区，正常最小列宽 340px | SimpleGrid |
| fields | 短表单字段，正常最小列宽 200px | SimpleGrid |
| metrics | 指标，正常最小列宽 140px | SimpleGrid |
| row | 可换行的操作和小标题 | Group |
| stack | 按 DOM 顺序纵向呈现 | Stack |
| surface:card | 有边框、内边距的功能区 | Paper / Stack |
| span:full | 跨整行的主要配置、长文本或说明 | 完整宽度容器 |

所有最小列宽用 `min(100%, …)` 限制，避免极窄容器溢出。仅有一张普通卡片时使用单列；跨行说明不能占据一个虚假的第二列。输入控件不再用各自 margin-bottom 与网格 gap 重复产生间距。数据表只在自己的滚动区横向滚动。

仅用于布局和条件可见性的 AI 包装层在快照边界展开，不再把 display:contents 带入可见视图。先检查 hidden，再展开；保留源控件 ID、顺序、草稿和事件处理器。新界面接管时暂停旧网格测量及自适应折叠控制；加载/渲染失败才恢复。折叠展开只有桥接状态一个所有者，分区跳转会先展开祖先折叠区。

工具栏只显示操作，保存状态与运行状态放在底部状态区，提醒在消息区；小窗口不再为了“已保存”独占一行工具栏。主题色、亮暗模式和材质继续使用原有统一变量。

## 验证与边界

自动测试覆盖透明包装展开、草稿编辑、原事件仅执行一次、键盘切换分类、状态分区、折叠跳转、旧布局暂停和失败回退。浏览器验证同时检查卡片宽度和页面溢出，避免“没有横向滚动条就算布局正确”的误判。桌面 / 390px 的 19 个页面、五种 AI 组合及更小窗口的最终结果见行动日志。

原 DOM 和业务控制器仍是兼容边界，不声称已经将所有领域模板改成纯 React。普通网格保持阅读顺序，不以重排或强制拉高短卡片来消除所有空白。动态数据、系统字体和新增长文仍需遵守本契约并验收。
