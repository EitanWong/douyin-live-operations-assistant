## PK 分析与直播互动助手

用户希望在同一工作台查看 PK 实时状态、分析己方/对方弹幕情绪与走向，估计胜率及“上票”、暴击卡、借力卡等行为概率，并让主播通过 @/指令唤起播报或小游戏。

| 方向 | 调研结论 | 工程取舍 |
| --- | --- | --- |
| PK 战况 | 抖音官方直播 SDK 文档描述了 PK 直播间和直播互动能力，但 SDK 有明确接入资质和权限流程；这不是普通网页扩展可直接复用的公开接口。官方方案列出的条件包括日活不低于 10 万、网络文化经营许可证及申请直播权限。 | 当前仓库的 protobuf 观察器没有 PK 数据类型，不能声称已能可靠读取比分、剩余时间或道具。只有接入获准的数据源并用真实样本验收后，才能填充实时面板。 |
| 对方弹幕情绪 | 对手房间弹幕需要另一个被授权的数据来源。当前直播页的连接只代表当前页收到的消息，不代表工具获准跨房间收集或分析。 | 只在平台授权和用户知情范围内处理消息；优先展示匿名聚合的主题/情绪趋势，并标明样本数、时间窗和数据延迟，不向第三方 AI 发送原始用户名/UID。 |
| 胜率与道具概率 | 分差、剩余时间、双方得分速度可构造可解释基线，但无法从一次比分快照可靠预测随机礼物、道具策略或观众消费意愿。LLM/Jev 的输出不能替代 PK 领域标签数据与回测。 | 先以比分、领先方、差距、双方近期得分速度和时间窗趋势作描述性统计。概率预测需按主播/场次拆分训练与测试，报告 Brier score、校准曲线和置信区间；冷启动/样本不足就显示“数据不足”。不估算具体观众的付费意愿。 |
| Jev 决策模型 | TypeSafe 官方资料将 Jev 介绍为输出带概率的结构化决策模型，并提供 `/v1/systemone` 与模型列表 API；适合分类、打分、路由类判断，但它不是 Douyin PK 专用预测模型，当前 AI 客户端只支持 Chat Completions。 | 将 Jev 作为可选“决策服务”需要新增独立协议适配、密钥域名授权、超时/预算控制与本地回退。先用 PK 历史样本和固定基线对比，再决定是否保留。模型文案也应注明概率不等于平台实测胜率。 |
| @场控与菜单 | 站内自然语言呼叫可映射为帮助、房间状态、常用互动、游戏等有限意图。游戏还要有状态机、回合超时、重复输入去重、主持人暂停/结束和跳过选项。 | 菜单先呈现在管理员侧边面板，生成供管理员确认的简短播报草稿。成语接龙、轻量问答等作为主持工具；真心话大冒险必须使用适龄、可跳过、非隐私、非强迫的题库。 |
| 自动播报 | 抖音用户协议（2026-02-13 更新，2026-02-20 生效）第 5.1 条写明，不得使用插件、自动化程序等接入抖音或收集/处理其中信息。即使网页能显示字段，也不表示插件自动读取或发言已获平台授权。 | 本项目不把机器人自动发布、跨房间抓取或自动封禁当作可默认交付能力。优先做只在获批数据源上运行的分析和人工确认；扩展当前的页面采集/发送能力前，必须先解决平台授权与产品接入路径。 |

用户协议与直播 SDK 接入门槛是本次能力边界的主要依据：[抖音用户服务协议第 5.1 条](https://www.douyin.com/draft/douyin_agreement/douyin_agreement_user.html?id=6773906068725565448)、[抖音直播 SDK 解决方案及接入资质](https://open.douyin.com/platform/resource/docs/ability/douyin-live-sdk/solution)、[TypeSafe Jev API 文档](https://api.typesafe.ai/redoc)、[TypeSafe Jev 介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。官方 SDK 页面说明的直播 SDK 主要用于第三方 App 观看和互动，不应推断其中包含本项目需要的直播间管理、跨房间评论分析或禁言接口。

礼物事件的钻石面值不等于主播到账金额。不同账号、活动与结算规则可能影响最终收入；本次公开资料没有找到可适用于所有主播的统一固定比例。根据用户提供的经验值，产品默认按 100 钻约 10 元礼物面值、主播分成约一半，即 0.05 元/钻估算，且允许按本人结算单调整。界面只称“收入估算”，未知礼物不计入面值并显示数量。准确实收需要平台提供或用户导入的结算单数据，目前未接入。

### 建议的建设顺序

1. **现场总览与按需功能**：房间连接状态、提醒、最近动作，以及按设置开关控制模块入口。这次界面改进交付了基础版本，不改变底层直播数据来源。
2. **授权 PK 摘要**：拿到许可源和真实事件样本后，先显示比分、剩余时间、领先差、近期得分速度、事件时间戳与来源健康度。
3. **解释性趋势估算**：提供短窗/长窗趋势、领先变化和不确定性。对道具行为只按已记录的场次事件统计，不把模型臆测当实时事实。
4. **经过回测的概率模型**：收集允许使用且含最终结果的场次数据；比较逻辑回归/贝叶斯基线与 Jev 等模型，分主播/对手/时间段评估校准，样本不够则不显示概率。
5. **主持人菜单与小游戏**：先做管理员操作面板和可确认播报草稿，再验证站内触发和播报的正式授权方式。

## 实现依据

普通网页脚本复用浏览器已有登录和直播连接，只观察原页面接收到的事件，不另建带签名的直播连接，也不自行发送 ACK/心跳。[抖音直播 SDK](https://open.douyin.com/platform/resource/docs/ability/douyin-live-sdk/introduction) 是官方能力介绍，不应视为普通油猴脚本的公开授权 API。

消息字段参考 [DouyinLiveWebFetcher 的 protobuf 定义](https://github.com/saermart/DouyinLiveWebFetcher/blob/main/protobuf/douyin.proto)，自行实现 wire reader，UID 始终保留为字符串。粉丝团状态、礼物累计值等都是待真实帧进一步验收的页面协议适配，不能保证平台变更后仍有效。

2026-10-14 获取的抖音公开发布代码显示公屏为富文本编辑器，输入上限为 50；发送图标会随空/非空状态替换。静态证据来自 [ChatRoom](https://lf-webcast-platform.bytetos.com/obj/webcast-platform-cdn/webcast/douyin_live/chunks/ChatRoom.b626dcc2.js)、[聊天编辑区域](https://lf-webcast-platform.bytetos.com/obj/webcast-platform-cdn/webcast/douyin_live/chunks/island_237ab.480da559.js)、[RichTextEditor](https://lf-webcast-platform.bytetos.com/obj/webcast-platform-cdn/webcast/douyin_live/chunks/RichTextEditor.82a7f2f5.js)。因此采用编辑器纯文本粘贴路径、重新定位发送图标、对比实际输入。静态代码核对不等于已完成真实发送测试。

AI 采用可编辑的 Chat Completions 兼容接口，服务资料：[DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[阿里云 DashScope](https://help.aliyun.com/en/model-studio/compatibility-of-openai-with-dashscope)、[火山方舟](https://docs.volcengine.com/docs/ark/chat-api?lang=zh)。模型名称以服务账号当前可用项为准。油猴注入与权限依据 [Tampermonkey 文档](https://www.tampermonkey.net/documentation.php)。
