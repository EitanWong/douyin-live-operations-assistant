# 项目结构与架构

## 目录

```text
src/
  app.js                  应用装配、配置与生命周期
  core/                   规则引擎、机器人会话、默认话术
  browser/                页面适配、协议解析、账号识别与运行锁
  data/                   礼物账本和持久存储
  runtime/                快照、日志确认、发送回显与有界交接
  services/               AI 客户端
  ui/                     场控面板
extension/                Manifest V3 入口、工具栏弹窗、图标和开发更新
demo/                     本地直播间模拟页面
scripts/                  构建、开发服务、语法检查与性能基准
tests/
  unit/                   规则、协议、服务和存储单元测试
  integration/            页面、扩展产物和开发更新集成测试
  helpers/                浏览器锁模拟与临时构建工具
docs/
  guides/                 使用与实测指南
  development/            架构、贡献和发布流程
  product/                产品范围
  reviews/                验证、稳定性和性能记录
  research/               历史调研与参考实现分析
  assets/                 文档截图，旧版界面放在 archive/
examples/                 可导入的示例配置
```

`dist/` 是生成目录；`output/` 和 `.playwright-cli/` 用于本地测试产物，均不纳入版本管理。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/app.js` | 装配引擎、面板、页面适配器、账本和持久化；管理启停、刷新与恢复 |
| `src/core/engine.js` | 互动条件、去重、礼物聚合、优先级调度、重试和运行快照 |
| `src/core/bot.js` | @指令、短菜单、房间游戏会话、回合与失败机制 |
| `src/core/phrases.js` | 默认话术和轮换 |
| `src/browser/protocol.js` | protobuf/gzip 解析、直播事件归一化、字符串 UID |
| `src/browser/adapter.js` | 观察页面连接、DOM 弹幕后备、输入与发送控件、Web Locks |
| `src/browser/identity.js` | 当前房间主播、登录账号和管理员资料识别 |
| `src/data/gifts.js` | 连击增量、按日/月记账、多主播存储与报表 |
| `src/runtime/journal.js` | 合并快照写入、有限批次确认、失败保留和退避 |
| `src/runtime/delivery.js` | 持久发送意图、账号/文本/时间回显关联、未知结果与显式处理 |
| `src/runtime/inbox.js` | 有界事件缓冲、有限重试、故障隔离、资源断路与恢复导出 |
| `src/services/ai.js` | 兼容接口、请求校验、超时与响应处理 |
| `src/ui/panel.js` | Shadow DOM 面板、功能开关、表单与状态展示 |

规则引擎和数据模块不依赖面板。新增业务规则优先放入对应模块，通过应用层接线；Chrome API 留在扩展入口。

## 消息流

1. `extension/page.js` 在 MAIN 世界观察直播页已有连接，把归一化事件交给隔离世界。初始化握手之前的事件先缓存。
2. `extension/content.js` 串行交接事件。运行期间和独立礼物记账均先经后台写入事件日志，再交给应用层。追加使用稳定 ID，重试不会生成重复日志；回放每页最多 256 条。
3. 应用层更新观众资料与账本任务，引擎执行互动规则、礼物连击合并和游戏逻辑。
4. 调度器优先处理礼物，并为等待中的机器人回复提供调度机会。发送控件串行处理，暂时失败的任务退避重试。
5. 自动发送前保存包含在途任务的检查点；已处理事件在快照保存成功后分批确认。

`extension/background.js` 负责扩展存储、房间范围校验、账本事务和已授权的 AI 请求。后台会被 Chrome 回收，业务状态保存在持久存储中。

## 状态与恢复

- 配置、运行快照、事件日志和收入账本按房间分开；AI 密钥按服务域名保存。
- 快照记录待发送任务、礼物累计、游戏会话、去重和冷却状态，以及待入账礼物。快照对象与运行状态隔离。
- 快照写入只保留一个在途写入和一个最新待写入状态；检查点必须等待实际保存成功。
- 事件日志每批最多确认 50 条，确认失败保留重试。该批次只影响存储交接，不限制弹幕发送频率。
- 页面刷新保存续跑意图，缓存返回恢复观察器。同房间通过 Web Locks 协调运行权。只有用户手动暂停会停止场控；配置保存在线更新，不清空互动现场。

发送前先保存待发送状态，真实点击前再保存点击意图。本人结构化弹幕回显在本人事件过滤之前匹配；超时、刷新与点击后中断进入未知状态，禁止自动重发。用户显式重试仍可能重复，不承诺恰好一次。尚未写入日志的事件、平台断线期间未重放的数据和被清除的浏览器存储无法靠本地快照补回。详细测试见[验证记录](../reviews/validation.zh-CN.md)。

## 构建

`scripts/build.mjs` 按模块依赖顺序生成单文件用户脚本和扩展 bundle，并复制后台依赖、弹窗和图标。源码目录分类不改变产物入口：Chrome 仍加载 `dist/chrome-extension`。

本地模拟器从源码模块启动；`npm run demo` 将根地址映射到 `demo/index.html`。开发更新由 `scripts/dev.mjs` 监听 `src/`、`extension/` 和 `scripts/`，构建成功后才发布新标识。

## 资源故障与降级

内容脚本交接和 MAIN 桥接各有 4,096 条 / 8 MiB 缓冲，解码最多排队 256 帧 / 16 MiB。瞬时故障最多重试三次，之后隔离；配额、80% 存储水位和业务背压立即打开断路。原始持久日志保留，恢复入口重新处理；不能写入或缓冲耗尽后的新增数据计为缺口。内存缓冲不是持久化保证。

礼物日志、待入账事实和感谢任务分别保留。待入账事实保存原采集时间，持久化快照中的事实可跨长时间故障继续入账；新到的历史补推仍按原时间规则过滤。未确认发送最多 100 条，普通待发送与礼物结算有独立容量边界。配额不足时不自动删除未完成业务数据，提供恢复导出并明确显示降级状态。
